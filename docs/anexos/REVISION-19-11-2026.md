# Revisión documental y actualización entre perfiles

Revisión del 19 de noviembre de 2026, rama `codex/revision-sprint2-documentacion-tiempo-real`.

## Cambios

Se añaden requisitos RF-08 a RF-17 con estado y evidencia, decisiones D1 a D10 con motivos/alternativas y guía de evaluación con cinco escenarios. Se sustituye el borrador Word del 5/11 por especificación vigente en Markdown y Word generado desde la misma fuente. Se corrigen destinatario y entrega obligatorios, estados de cancelación/revisión/ejecución, ocho PBI y 50 unidades de estimación. El seguimiento separa estado actual e historial; no se cambia la sesión actual de Overleaf ni el tablero.

Los requisitos y decisiones se presentan en apartados cortos, sin tablas anchas, para poder leerlos tanto en GitHub como en el editor de texto.

El panel consulta cambios cada cinco segundos desde comunicación, sin consultas solapadas. Conserva filtros, evita actualizar durante edición o diálogos y descarta respuestas tras terminar la observación. Un fallo de red se reintenta sin sustituir la última vista. Se trasladan a `cliente/rest.js` las URLs de recursos, planificación y entregas que estaban en componentes visuales.

## Verificación local

`npm test`, Node.js 24 y SQLite desechable: **91 casos, 89 superados, 0 fallos, 2 omitidos** por no disponer de `MONGODB_TEST_URL` local. Las primeras pruebas HTTP fallaron con EACCES del sandbox; se repitieron con acceso a loopback y pasaron. No fue un fallo funcional del servidor.

Las pruebas nuevas cubren pausa, recuperación de red, ausencia de solapamiento, descarte tras cerrar sesión y abrir edición durante una lectura y controles ocultos de sesiones anteriores. Una integración HTTP con dos cuentas reales de prueba ejecuta el observador del cliente, realiza una aceptación administrativa y recibe el nuevo estado en el siguiente ciclo sin recargar. Las pruebas existentes de planificación y entregas siguen pasando con los métodos de comunicación extraídos.

La especificación Word se convierte a PDF con Microsoft Word instalado para revisar su maquetación, porque LibreOffice no está disponible. Las salidas de QA son temporales y no forman parte de la entrega. La conexión al navegador de revisión no estuvo operativa; no se presenta como realizada una nueva prueba visual móvil o una prueba manual de dos navegadores. La guía deja esos pasos reproducibles.

## CI y límites

GitHub Actions ejecuta también las integraciones MongoDB con replica set y el contenedor. El estado y la versión exacta de esta revisión se consultan en la pull request que contiene este archivo; las cifras de CI deben proceder de esa ejecución, no de la revisión histórica de P24.

El sondeo actualiza listados y métricas, no reemplaza detalles abiertos ni borradores de planificación. Tiene latencia de un ciclo más red. Correo, consentimiento Google y aceptación académica requieren sus comprobaciones independientes. El contenido documenta estos límites sin afirmar una validación que no se haya ejecutado.
